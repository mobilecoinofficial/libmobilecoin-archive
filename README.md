## Repository Structure
|Directory |Description |
| :-- | :-- |
| [Sources](./Sources) | Autogenerated grpc protobufs. |
| [Vendor](./Vendor) | Committed misty-swap protos, plus the pinned foundation revision that `make vendor` fetches into `Vendor/mobilecoin`. |
| [tools](./tools) | Build and packaging scripts. |

Each release attaches `LibMobileCoinLibrary.xcframework.zip` as a GitHub
release asset. SwiftPM pulls it through `.binaryTarget(url:checksum:)` and
CocoaPods pulls the same archive in `prepare_command`, both verified against
the same SHA256. The repository carries no prebuilt binary, so neither consumer
needs git-lfs.

`make package` rebuilds that archive from a local `make` build. The script
normalizes mode, mtime and entry order, so the same xcframework tree always
produces the same checksum.

`Vendor/mobilecoin` is not a submodule. `Vendor/mobilecoin.rev` holds
the pinned foundation revision and `make vendor` runs `tools/fetch-vendor.sh`
to check it out at depth 1. SwiftPM runs `submodule update --init` on every
dependency checkout, so a submodule here would reach every consumer that only
wants the prebuilt binary.

If `Vendor/mobilecoin` is a submodule checkout in your clone, the build stops
with instructions rather than deleting it. Save anything uncommitted in there,
then:

```sh
git submodule deinit -f Vendor/mobilecoin
rm -rf .git/modules/Vendor/mobilecoin Vendor/mobilecoin
```

To fetch from a mirror instead, set `MOBILECOIN_REMOTE`. The mirror needs
`uploadpack.allowAnySHA1InWant`, because the fetch asks for a bare SHA.

`LibMobileCoinTestVectors` is a separate product. The four `LibMobileCoinCore*`
products carry no test fixtures, so a shipping app does not embed the vectors
bundle. Test targets add the product explicitly.

`Sources/Common/PrivacyInfo.xcprivacy` is the privacy manifest. SwiftPM ships it
as a resource of `LibMobileCoinCommon` and CocoaPods ships it in the
`LibMobileCoin_Privacy` resource bundle, so both consumers get one copy.

## Releasing

`release.env` holds the version and the checksum of the released xcframework.
`Package.swift`, `LibMobileCoin.podspec` and the `Makefile` all read it, so a
release changes one file.

To cut a release, bump `VERSION` in `release.env` on master, then run the
**Release** workflow from the Actions tab. It builds the xcframework, writes the
new checksum into `release.env`, commits that, creates the `v<VERSION>` tag,
attaches the archive to the GitHub release, and pushes the pod.

The workflow does not trigger on a tag push. The tagged commit has to already
carry the asset checksum, and that is only known once the Rust build finishes.
`make publish` does the same sequence locally.

The **PR** workflow resolves and builds the SwiftPM package and lints every
podspec subspec. Resolving verifies the binary target against
`XCFRAMEWORK_SHA256`, so a stale checksum fails there.

## Overview

MobileCoin is a payment network with no central authority. The fundamental goal of the network is to safely and 
efficiently enable the exchange of value, represented as fractional ownership of the total value of the network. 
Like most cryptocurrencies, MobileCoin maintains a permanent and immutable record of all successfully completed 
payments in a blockchain data structure. Cryptography is used extensively to establish ownership, control transfers, 
and to preserve cash-like privacy for users.

For more information about the cryptocurrency, see [MobileCoinFoundation/MobileCoin](https://github.com/mobilecoinfoundation/mobilecoin).
